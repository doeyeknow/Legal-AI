# Billing setup and release checklist

The interview and motion catalog remain public. A $5 USD one-time purchase downloads one motion PDF with its filing instructions, without requiring an account. An active membership includes unlimited motion downloads and access to the dashboard and member tools. Weekly and yearly memberships renew until cancelled; lifetime is one payment.

## Before deploying to customers

1. In Stripe, create prices for $10 USD recurring every week, $50 USD recurring every year, and $100 USD one-time. Configure the corresponding `STRIPE_MEMBERSHIP_WEEKLY_PRICE_ID`, `STRIPE_MEMBERSHIP_YEARLY_PRICE_ID`, and `STRIPE_MEMBERSHIP_LIFETIME_PRICE_ID` on the app. The server validates each price’s economics and Stripe mode before starting checkout. Use test-mode prices and keys for a preview, and live-mode ones for production.
2. Keep the existing `STRIPE_SECRET_KEY`, `SESSION_SECRET`, Postgres connection, and `NEXT_PUBLIC_SITE_URL` configured. If the site is also served from an owned domain that is neither the canonical URL nor a Vercel deployment domain, add its exact origin to the comma-separated `CHECKOUT_ALLOWED_ORIGINS`. Return URLs stay on the origin where the interview was completed.
3. Add a Stripe [webhook event destination](https://docs.stripe.com/billing/subscriptions/webhooks) at `/api/webhooks/stripe` on the deployment’s HTTPS origin. Use a current event API version compatible with the installed Stripe SDK. Subscribe to `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.paid`, `invoice.payment_failed`, and `charge.refunded`. Set the endpoint signing secret as `STRIPE_MEMBERSHIP_WEBHOOK_SECRET`. A protected Vercel preview may need explicit configuration to receive test Stripe webhooks.
4. Enable the [Stripe customer portal](https://docs.stripe.com/customer-management/integrate-customer-portal) for payment-method updates, invoice history, and subscription cancellation. Use end-of-period cancellation if customers should keep access through their current paid term. Leave plan switching disabled in the portal, since this application does not support billing credits or migration between an existing recurring plan and a lifetime purchase. If Stripe is still retrying a failed renewal, members must manage their existing subscription rather than buy a second plan.
5. Before merging to the production branch, verify end-to-end in Stripe test mode: a guest’s $5 checkout, return to the same answers and PDF download; new weekly, yearly and lifetime memberships; subscriber download with no extra charge; dashboard access from a fresh session; cancelling, a failed renewal, and refunding a lifetime purchase. Check the delivered PDF for appended pages clearly labeled “do not file.”

The schema change is additive and uses the app’s existing schema initialization. Existing accounts and saved cases are not deleted or automatically granted membership. Previously paid $3 sessions remain redeemable for their original motion; their first redemption binds them to the downloaded answers. Nonmembers who bought a one-time motion should keep the download and receipt, since the checkout uses the same browser tab’s draft and does not store the PDF in a dashboard.

Optional, server-only settings: `LEGAL_FREE_COUPONS` is a comma-separated list of explicitly approved free-motion codes. The development `LEGAL_DEV_FREE=1` bypass does not run in production. Do not reuse publicly known old promo codes.

The homepage presents the $10 comparison price with a strikethrough as requested. Verify that the comparison can be substantiated before advertising it publicly; the previous app’s advertised motion price was $3.
